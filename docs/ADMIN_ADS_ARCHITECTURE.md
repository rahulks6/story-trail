# Admin and Sponsored Stories architecture

Baseline: React Native 0.75.4 / React 18.3.1; React Navigation 6 keeps six consumer tabs. Node 20+ TypeScript CommonJS custom Router serves /api/v1. JWT access/rotating refresh tokens and scrypt passwords remain the consumer authentication mechanism. PostgreSQL 19 existing migrations; psql CLI data adapter. Local MediaStorage validates uploaded JPEG/PNG/MP4 before storage. Stories reference media with 24-hour expiry and soft deletion; Highlights retain expired Stories. Organic recommendations rank eligible creators using engagement events; ad delivery will not write those events or modify scoring. Existing reports support Story/comment/user targets; blocks and private profiles gate organic access. Existing moderation uses is_moderator and has no audit trail. No advertising implementation exists. Docker Compose deploys PostgreSQL/backend/Caddy; no native ios/android build directories exist. No Git metadata or AGENTS.md is present in the supplied archive.

Implementation phases follow the requested order: additive migrations; explicit RBAC; separate cookie-session web console; Admin management; existing report queue with atomic moderation/audit; isolated ads backend and admin screens; sponsored playback/insertion; event/hide/report; security/regression/performance validation.

Safety decisions: flags default off; no data resets or table renames; existing consumer auth and routes retained. A default USER has no privileged grant. Legacy moderators are migrated to explicit restricted ADMIN grants, never SUPER_ADMIN. Only an operator bootstrap command can create the first SUPER_ADMIN. Web sessions are separate, hashed server-side, expire, require same-origin CSRF protection, and recheck live grants on every request. Highly sensitive changes require a recent password check. MFA extension fields are reserved; MFA is not claimed implemented. *(Superseded: Admin TOTP two-step verification with backup codes was implemented in Phase 1.)* No general DM moderation browser or DM-based targeting is added.

V1 targeting: untargeted eligible signed-in audience only, with advertiser block/privacy checks; no age/location/sensitive inference. *(Phase 4 update: campaigns may name up to 5 of 20 fixed, non-sensitive interest categories and/or Android/iOS, checked in `reserve_ad` against interests people chose themselves; see `ADMIN_ADS_RELEASE.md` and `docs/phases/PHASE_4_MODERATION_ADS_ANALYTICS.md`.)* No payment processor or billing: campaign budgets are stored planning metadata, delivery uses a separate hard impression allocation and analytics show spend as unavailable. Ads use existing validated media. A delivery reservation is not an impression. Events require a viewer-owned delivery, deduplicate by delivery/event type, and count an impression only after one second visible. Reserved slots conservatively count toward caps to avoid concurrent over-delivery.

Release gates: staging migration and recovery rehearsal, live PostgreSQL integration suite, native gesture/device regression, and before/after device/API latency measurements. These cannot be replaced by mocked checks or source inspection.
